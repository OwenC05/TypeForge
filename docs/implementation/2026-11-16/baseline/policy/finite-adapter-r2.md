## Adapter seam and precedence

`createFiniteAdapter({id,snapshot})` in `interfaces-r2.ts` receives the deeply immutable certified ordered plan, not a corpus selector or mutable queue. It must pass **only those exact prompt IDs/texts in that order** to the producer. No runtime search, expansion, modulo continuation, rotation, uncatalogued cycling or appended separator passage. The catalogue certifies 480/491/501/502 prompt characters; submission spaces are input actions, not extra certified prompt characters or delivered-dose counters.

The instrument owner adds an explicit finite option and distinct terminal state to the engine. At a boundary action, advance the monotonic timer **first**, exactly as the current engine does. If it expires at/before that action, ordinary `timeout` wins and no final commit/plan-end is invented. Otherwise commit the current sentence using existing editing, integrity, limit and pair semantics. Only after the final certified commit, atomically enter `plan-exhausted`; do not query modulo `currentPrompt/nextPrompt` for another context. Last-context next-prompt is null; actual Claude renders the end marker. All subsequent edits/ticks cannot admit text or increase elapsed/metrics; restart requires a new ID/snapshot. The end occurs immediately with actual elapsed time; no waiting for the nominal deadline and no early `completed`/30s relabel.

Safety-limit failure has its existing `stopped` snapshot and never becomes plan-exhausted. Abort/restart/page disposal remain aborted with no saved timed completion. Focus loss/invalid input preserve run flags, sentence eligibility and diagnostics. If flagged input subsequently reaches the finite end, the new envelope retains those flags and is never shown as a clean timed completion; the existing interruption/invalid-input explanation takes precedence over the ordinary end observation. This needs Claude/engine integration acceptance; no flag is cleared to obtain an eligible outcome. Editing/backspace/repeat affect sentence metrics exactly as before; sentence advancement is existing submitted-boundary behavior, not proof of clean traversal or realized exposure. Timeout before the end may include the same ordinary unfinished last sentence; do not recalculate saved schema1 results.

## Minimum producer/result boundary

Current `TypingEngine.metrics()` already uses actual `elapsed`:

```
wpm = elapsedMs > 0 ? correctCharacters * 12000 / elapsedMs : 0
accuracy = diagnostics && attemptedCharacters > 0
  ? correctAttempts / attemptedCharacters * 100 : null
```

`correctCharacters` is retained matching prompt characters plus matching current-response characters, with deleted characters reported separately. Submission spaces are not new character attempts. These formulas can be retained truthfully at a finite end: elapsed is the same monotonic first-input span, accuracy retains its diagnostic/null condition. They do not estimate interval clock span, learning or an equivalent 30s score. The r2 producer probe obtains the actual snapshot at final submission and verifies these formulas; it does **not** make the current `result()` accept early results.

Current `result()` returns only in state `completed`. `validateResult()` requires `metrics.elapsedMs===settings.durationMs` and its WPM bound/formula uses that duration. Therefore an early plan end **cannot** be saved or cast as a schema1 SessionResult by setting `eligibleForProgress=false`, inventing a flag, changing duration to elapsed, padding time, or adding unknown terminal fields. It needs the separate strict `FinitePracticeResult` source envelope declared in `interfaces-r2.ts` and a separate validator, implemented by the instrument owner. Existing schema1/metric1 validators and calculation/cohort meanings stay unchanged. MetricVersion1 here identifies the existing formula, not timed-run eligibility. This does not introduce metric2 Undo.

The new envelope has `schemaId=typeforge-finite-practice-result-v1`, actual end UTC in `completedAt` (shared physical index, not a timed-completion claim), UUID/guest/practice/metricVersion1, `termination=plan-exhausted`, `eligibleForProgress=false`, unchanged chosen settings, actual metrics/flags/submitted sentences/chart, and minimal plan identity `{configId,catalogueId,planHash,pair,sentenceCount}`. Validate exact keys, <=1-MiB total, existing scalar/sentence/attempt limits, original metrics formulas over **actual positive elapsed<30000**, diagnostic/flag/null semantics, monotonically ordered chart samples within actual elapsed, exact submitted sentence count/order/immutable prompt identity and plan hash. Missing/nonfinite/zero elapsed or inconsistent metrics means figures unavailable and source rejected to diagnostic export, never fabricated numbers. `correctAttempts<=attemptedCharacters`, safe counts and finite output remain mandatory. The schema1 timed WPM maximum must not be reused for early-source validation: very fast synthetic input can validly exceed it with positive actual elapsed.
