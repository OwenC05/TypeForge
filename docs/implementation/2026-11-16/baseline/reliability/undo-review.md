## Proposed implementation slices, in dependency order

1. **Freeze semantics and metric context with P1/root before coding.** All new runs would use metric 2 from creation, retaining schema 1 and flow-v1 unless review explicitly changes that contract. Keep old result payloads and frozen model evidence immutable. Commit metric migration separately from P3's additive bounded-history foundation.
2. **Engine-owned accepted transactions and preview/admission.** Add a bounded passage journal and explicit replay request, distinct from ordinary `Edit`. App owns observed native events and selection; engine owns counters, passage identity, accepted journal/cursor and limits. Candidate evaluation must be pure until admission. Return an explicit accepted/rejected/unsupported outcome so app can restore value/range without guessing from a boolean. Avoid feeding replay restoration through the ordinary insertion-counting loop.
3. **Native adapter.** Capture accepted before/after value, range **and selection direction**, passage epoch, accepted-edit sequence, input type and available physical-key evidence. Journal only admitted edits; never retain printable-key streams in persistent results. On native history input, enumerate only direction-consistent contiguous Undo/Redo paths from the accepted cursor inside this passage. Validate every transaction's exact source range/deleted text and target value, then compare the complete candidate endpoint with the browser result. Match selection only using supported recorded/native observations; unexplained selection must not be invented.
4. **Unique replay only.** Require exactly one justified history transaction/group, including its removal count and cursor destination. Repeated strings, equal-text replacement, same endpoint at multiple journal boundaries, mixed edit groups, missing beforeinput, composition, and history surviving programmatic restoration can be ambiguous. Do not choose the shortest diff or first matching endpoint. Accept supported coalescing of adjacent recorded edits only when the composed transaction and removed span are uniquely explained. Initially fall back on mixed coalescing when intermediate journal transformations do not establish the browser's actual removal transaction; do not charge fictional intermediate reconstruction steps as actual removals. Ordinary native word deletion uses captured range/direction and exact before/after equality, not guessed word-boundary rules.
5. **Admission and replay accounting.** Compute actual removals from the justified ordinary/composed history transaction. Before mutating accepted text, counters, journal, sentence flags, timing or prediction evidence, check cumulative session deletions + removals <= 16,384 and existing response/attempt/sentence/result bounds. A replacement removes its entire replaced range even if some replacement characters equal old characters. Replay restores text without incrementing attempts, correct attempts, first attempts/errors or seen-position state. New physical insertion after Undo counts normally and invalidates the Redo branch. Mark every supported replay's touched sentence edited, clear timing continuity and omit all its pair/matched-prediction output. Previously committed summaries and frozen prediction identities remain unchanged. Accuracy remains usable absent another unsupported/interruption reason.
6. **Atomic rejection and conservative fallback.** Cancel beforeinput when a provable over-limit transaction is known and cancelable; otherwise restore the last accepted value and pre-edit selection including direction after input. Rejection alone must leave accepted accuracy, journal/cursor and diagnostic evidence unchanged. Do not call today's mutating `edit` merely to discover whether a replay fits: it sets sentenceEdited and advances/samples before full admission. Let the clock continue normally, but prevent a rejected candidate from creating a typing/timing/prediction observation; separate ordinary clock sampling from edit admission. Surface the deletion-limit outcome through the existing feedback contract (Claude owns presentation). A later history mismatch uses unsupported-input handling, never fabricated reconciliation. Cross-commit history must restore the active passage, cannot alter a committed summary, and takes explicit unsupported fallback. Exhaustion/ambiguity preserves honest null-accuracy behavior and notice, not an invented clean result.

### Explicit journal proposal (review settings, not shipped constants)

Use at most **1,024 accepted edit entries per active passage**, **4,096 admitted replay events per session**, and **32,768 total retained inserted/deleted UTF-16 code units in journal payloads**. Keep the existing response 600, prompt 300 and insertion-attempt 16,384 caps. No-op/navigation events create no entries. A pure insertion entry stores range/inserted text plus selection metadata; replacement stores deleted/inserted spans once, not full duplicated response snapshots. A candidate matcher explores at most the bounded entry count in each direction with bounded response intermediates; no combinatorial subsequence search. Proposed bounds need measurement/review in the future lane; this report makes no latency claim.

Entry/payload overflow must atomically stop extending trusted history and enter conservative unsupported history behavior; never silently evict evidence and claim an older replay is justified. This can conservatively mark the run unsupported, with an explicit reason, while ordinary editing/completion/restart remains usable. Replay-operation overflow rejects trusted replay and takes the same documented unsupported route. Commit clears active journal/cursor and changes passage epoch but **does not reset session deletion or replay totals**. Restart creates a fresh run and resets both. The 600-character stress fixture below uses 600 initial insertion entries plus fewer than 30 deletion entries and 30 restorations, so these caps do not accidentally prevent the required deletion-bound reachability. Journal caps and deletion caps are independent: neither substitutes for the other.
