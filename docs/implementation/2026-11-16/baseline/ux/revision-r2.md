## Interface requests to root/P1 (UI needs; not policy)

- Expose `automaticCoaching` on the status, read from config `releaseScope.automaticCoachingEnabled`. Copy must never infer this.
- Keep `baselineProofComplete` and `summarySelectionProofComplete` as separate fields. Keep `evidenceScanComplete` nullable.
- Widen the UI's `pendingSave` to mean "completed in this tab, not yet durably saved, still retryable". A failed save stays pending until it is retried or the page goes away. On reload the count is re-derived and the ordinal reuses the number (contract rule 4).
- Summary: `summaryState`, `medianWpm`, `medianAccuracy`, `validAccuracySources` and the UTC `timeRange` as specified. The UI shows dates only, in the user's locale, as given.
- Finite plan: a plan-exhausted completion distinct from timeout, actual `elapsedMs`, a sentence count, and the metric-validity ruling (see `finite-plan-end.md`).

## Limits

The prototype is a fixture simulation with simulated save delays and failures, and a 10× clock where `fast=1`. It is not the production engine, storage, bounded read or selector, and late reads during typing are modelled only through the save path. Testing used headless Chromium only, with emulated viewports and forced colours. There was no Windows High Contrast theme, screen reader, IME, physical device or human participant. Scripts are not comprehension: the review's acceptance criterion 10 (a short human check) is still open. Full-page captures at 320/390 show the production skip link mid-page. That is a capture artifact: `position: fixed; top: -100px` is stitched at the scroll offset. It is not visible in viewport captures.
